## 一、公式：`\(...\)` / `\[...\]` 被静默吞掉

**现象**

- `\(R^2\)` 排成字面量 `(R^2)`
- 行间公式 `\[ E_c=\frac{...} \]` 变成 `[ E_c= ]` 这种残骸
- 转换退出码 0、零告警，只有打开 docx 才发现公式没了

**根因**

pandoc 的 `markdown` reader **默认不开** `tex_math_single_backslash`：

- `\(` 被当成转义的括号 → 字面量 `(`
- `\[ ... \]` 里的 `\frac{}{}` 变成 `RawInline (Format "tex")`，docx writer 直接丢弃

**修复**

`tools/convert.sh` 的 reader 加 `+tex_math_single_backslash`：

```
-f markdown-raw_attribute+tex_math_single_backslash
```

**锁住**

`tests/cases/T17_backslash_math.md`：断言 `\(...\)`/`\[...\]` 变成真公式、没有
LaTeX 命令残留、按章编号正确。反向验证过：去掉扩展立刻变红。

## 二、图片上传与图题

### 2.1 服务原来只收单个 `.md`

**做法**

- `/convert` 的 `file` 支持 `.md` **或压缩包**（zip / tar 系 / 7z / rar）
- 也可以额外用 `images[]` 字段单独传图片（可多张）
- 一个 md → 一个 docx；多个 md → 每个一个 docx，打包成 zip；空 md → 空 docx

### 2.2 Obsidian 的 `![[...]]`、任意文件夹名

**现象**：真实 Obsidian 导出包用 `![[figures/2-1.png]]`，pandoc 当纯文本，
**31 张图一张都进不去**；同一份文档里 `figures/x.png` 和裸 `x.png` 还会混着写。

**做法**：新增 `tools/resolve_resources.py`（CLI/服务共用）

- `![[path]]` → 标准图片；`![[path|300]]` 当宽度、`![[path|说明]]` 当图题、
  `![[path|120x80]]` 取宽度
- 解析顺序：相对 md 的**精确路径** → 整个包内**按文件名**找
- 文件夹名任意（figures / images / pics / 图片 …）；`../figures/x.png` 也支持
- 只允许搜索根目录内的文件（服务端根 = 解压目录/请求目录），绝对路径、URL 一律不读
- 找不到的图片列出文件名；同名图片无法确定时警告并跳过
- **用户的原 md 一个字不改**，只改写临时副本

### 2.3 图题

优先级：**图下加粗行 > alt / Obsidian 别名 > 文件名**。

- 图号一律按章、按出现顺序重编（`图2-1`）
- 纯编号文件名（`2-1.png`）只排「图2-1」；描述性文件名（`云服务器架构.png`）排
  「图2-1 云服务器架构」
- 每张**独立成段**的图都出题注；行内图、列表项里的图不动
- 修掉了「alt + 加粗行 = 双题注」
- 修掉了「`**图表解读：…**` 被误判成图题（拆成 图 + 表解读）」
- 图片段落套模板的 `图片` 样式（居中）；题注套 `图下面的文字`
- 用户模板缺 `图片`/`图下面的文字` 时从基准模板补齐

**限制**：列表项里的图（`1. 说明` 下一行缩进 `![[...]]`）只嵌入、不加题注 ——
它们不是独立段落，硬拆会改变列表结构。

## 三、代码块与行内代码

**现象**：AI 生成的报告把公式写在 ` ```text ` 里，转换后是 Source Code
（Fira Code + 灰底），中文和公式都很难看；行内代码 `` `read_csv()` `` 同样难看。

**做法**

| 输入 | 处理 |
|---|---|
| ` ```math` / ` ```latex` / ` ```tex` | 无条件转公式 |
| ` ```python` / ` ```js` / ` ```bash` / ` ```code` | 永远是代码，不动 |
| ` ```text` / 无语言 + 像公式的行 | 转真 Word 公式，按章编号 |
| 公式行 + 说明文字混排 | 只转公式行，说明文字转普通正文 |
| 非公式 text 块 | 转普通正文（不再用等宽字体） |
| 行内代码 | 转普通文本 |

- 判定保守：有 `=` 之类关系符、无代码语法、含中文/数学运算符/函数名
- 中文走 `\text{}`，标识符走 `\mathit{}`，多行合并为 `array` 公式组
- 转换结果作为 **guess** 汇报；误判时把语言标记改成 `python`/`code` 即可
- 行内公式请用 `$…$`；行内代码转公式会把 `read_csv` 的下划线变下标，反而错

**锁住**：`T23_code_formula.md`。

## 四、列表：去掉项目符号

**依据**：GB/T 7713.1 和各校撰写规范都采用「分层编号 + 按层级缩进」，
不使用 •、■ 这类项目符号。

| 输入 | 输出 |
|---|---|
| 一级无序项 `- xxx` | 正文段落，首行缩进 2 字 |
| 二级及以下 | 左缩进 2 字符/级 +「（1）（2）」编号（每个父项内重新计数） |
| 有序列表 `1.` | 保持 Word 自动编号 |

- 模板新增 `列表正文二级/三级/四级` 样式（左缩进 2/4/6 字符、首行不额外缩进）
- 用户模板缺这些样式时从基准模板补齐
- 测试 `T24_lists.md`；主用例基线差异：3 个 `Compact → Body Text`，列表后那段
  `First Paragraph → Body Text`，其余不变

## 五、标题与不编号章节

### 5.1 多 md 包：文件名把真标题顶掉了

**现象**：`outputs (2).zip` 有 2 个 md，转换后文件名变成「摘要上标题」，
真正的 H1 被降成第一章，第一页后面还多一页空白。

**根因**：多文件包原来**无条件**用文件名当大标题、把所有 H1 降级。

**修复**（`app/convert.py: _has_single_h1`）：

| md 里的 H1 数量 | 大标题来源 |
|---|---|
| 恰好 1 个（完整论文/报告） | **用这个 H1** |
| 0 个（分章笔记） | 用文件名 |
| 2 个以上（层级有歧义） | 用文件名，H1 全部降为章（HCCDA 的包行为不变） |

### 5.2 摘要/目录/参考文献/致谢/附录不占章号

**做法**：

- 摘要 → 原有 `摘要` 样式（本来就不编号）
- 目录 → 原有 `目录两个字` 样式
- 参考文献 / 参考资料 / 致谢 / 附录 / Abstract / 符号说明 / 攻读学位期间…
  → 新增 `不编号标题` 样式（照 heading 2 克隆，`numId=0`）
- 这些标题**不参与章号计数**，不影响后面的章节编号；大纲级别保留，所以仍进目录，
  只是目录里不带章号

**锁住**：`T25_unnumbered.md`；主用例基线：`heading 2 -1 → 不编号标题 +1`，
参考文献后那段 `First Paragraph → Body Text`，其余不变。

## 六、目录后的空白页（本轮最麻烦）

**现象**：目录很长时，在 WPS 里按 F9 更新目录后，目录和第一章之间多一页空白；
目录短时没有。LibreOffice 渲染不出来，只有 WPS 复现。

**根因**

WPS 更新 TOC 域后，会在域结果末尾保留一个**只放 `fldChar end` 的空段落**。
目录刚好填满一页时，这个空段被挤到下一页；第一章标题的 `heading 2` 带
「段前分页」，于是又翻一页 → 中间那页只有空段（和页脚页码），看起来就是空白页。
目录短时空段留在同一页，所以看不到。

**试过但不行 / 不完整的方案**

| 方案 | 结果 |
|---|---|
| 把结束段压成 1pt（字号/固定行距） | LibreOffice 有效；WPS 仍按整行高排，页码/页数不变 |
| 给结束段加 `keepNext` | LibreOffice 仍空白 |
| 隐藏 + 1pt（`w:vanish`） | WPS 更新后保留了属性，但空白页仍在 |
| 去掉结束段、把 end 放进最后一条目录（`after-F9-merged`） | **WPS 正常**，段前分页也正常 |
| 去掉第一章「段前分页」 | 空白页没了，但章不再另起页 ✗ |

**最终方案**（已固化进 `tools/build_toc.py: move_end_into_heading`）

目录域结构改成：

```
[目录标题段]
[域开始段：begin + TOC 指令 + separate + F9 提示]
[第1章 标题段：<域结束符> + 第1章 引言]
```

- 结束符放进**第一章标题段开头**：WPS 更新目录后，域结果后面直接是第一章，
  没有位置再补末尾空段
- F9 提示从独立占位段挪到域开始段（F9 时被目录条目替换）
- 独立的占位段/结束段整个删掉
- 第一章的段前分页保持不动

**验证**

- 用户 WPS 实测：F9 正常生成目录/页码，无空白页，每章正常另起一页
- 62 条目录的极限渲染：无空白页
- 回归/冒烟断言锁住「结束符在第一章标题段开头、没有独立空段」

## 七、压缩包格式

**支持**（按文件头识别，扩展名/文件名无所谓）：

| 格式 | 解包方式 |
|---|---|
| zip | Python `zipfile`（原有加固逻辑） |
| tar / tar.gz / tgz / tar.bz2 / tbz2 / tar.xz / txz | Python `tarfile` |
| tar.zst | 7z / bsdtar |
| 7z | 优先 `7z`/`7zz`，失败回退 `bsdtar` |
| rar（RAR4 / RAR5） | 同上 |

**安全**：解压前列清单（条目数、解压后总量、加密标记、路径、符号链接）；
解压后再走一遍树；加密包、路径穿越、符号链接一律拒绝。

**依赖**：Dockerfile 加 `7zip` + `libarchive-tools`（Debian 主仓库的 7zip
不含 unRAR 代码，rar 实际走 bsdtar）。

**限制**：单文件 `.gz/.bz2/.xz` 需先打成 tar；极少数特殊压缩方法的 RAR5
可能两个工具都解不了，建议改用 zip 重新打包。

## 八、另一个 AI 报的两个 Word 兼容问题（2026-10-17 补充）

这两条在 WPS 下都看不出来，是另一位在 Microsoft Word 里实测报的；本机没有 Word，
但**包结构层面都确认属实**。

### 8.1 docx 包里的目录条目让 Word 拒绝打开

**现象**：WPS 正常，Microsoft Word 报「文件可能已经损坏」，直接打不开。

**根因**：pandoc 使用参考模板生成 docx 时，会把模板里的 `word/media/` **目录条目**
带进输出，并在 `[Content_Types].xml` 里写一个
`<Override PartName="/word/media/" .../>`。OPC 规范里 part 不能是目录；
WPS 宽容地忽略，Word 直接拒绝整个包。

实测确认：裸 `pandoc`（不带 `--reference-doc`）没有这个条目；带上我们的模板就有。
所以是「模板里的目录条目被 pandoc 带出来」+ pandoc 给它补了一个 Content_Types 覆盖。

**修复**：新增 `tools/clean_docx_dirs.py`，在 `convert.sh` 最后一步清掉所有
目录条目和指向目录的 Override。不改任何正文内容。

**锁住**：回归里**每个用例**都断言最终 docx 的「目录条目数 | 目录 Override 数」= `0|0`；
接口冒烟也加了一条。

### 8.2 公式表继承了「三线表」样式

**现象**：WPS 里公式表无框；Word 里公式上下各有一条线。

**根因**：公式表确实把六条边都写成了直接格式 `nil`，但表格上还挂着
`tblStyle="Table"`（模板的三线表样式，带上下 `sz=12` 粗边框）。
WPS 按「直接格式优先」显示无框；Word 对样式/直接格式的合并更保守，
仍可能套用样式的上下边框。

**修复**：`tools/set_table_borders.py: _fix_formula_table` 去掉公式表的 `tblStyle`，
只保留直接格式（固定列宽 / 六边 nil / 固定布局）。数据表不动（三线表还要用这个样式）。

**锁住**：T15 断言公式表里没有 `tblStyle`，同时保留「六边 nil」和列宽不变量。

> 修复不改正文；WPS 用户观感不变。

## 十、一句话清单

- 公式没了 → 检查 `tex_math_single_backslash`
- 图片没进去 → 检查 `![[...]]` / 文件夹名 / 文件名匹配 / 缺图警告
- 图题不对 → 加粗行 > alt > 文件名；`图表解读` 不是题注
- 代码块太丑 → 语言标记；` ```code ` 强制代码
- 列表有点 → 无序转正文、嵌套缩进 +（1）（2）
- 文件名变大标题 → 有且只有一个 H1 时用 H1
- 参考文献被编号 → `不编号标题` 样式
- 目录后空白页 → 结束符放进第一章标题段，别留独立空段
- 压缩包解不开 → 看格式/加密/工具；服务端已装 7zip + bsdtar
- Word 打不开 → 清掉 docx 包里的目录条目和 Content_Types 目录 Override
- Word 里公式有两条线 → 公式表去掉 tblStyle（不要只依赖直接 nil 边框）
