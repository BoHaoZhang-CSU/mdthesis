# Markdown 书写规范

这份规范描述「用本项目的转换器生成 Word 论文」时，markdown 应该怎么写。

**为什么需要规范**：转换器把 markdown 的标题层级映射到 Word 的样式，再交给模板自动编号和分页。
层级用错，输出就会错位 —— 而且**不一定报错**，只是悄悄变丑。所以请照着写。

---

## 一、规范正文

### 1. 一级标题 `#` 只能出现一次，且只能是文档大标题

文档大标题会被套上「摘要上标题」样式（黑体、18pt、居中、**不编号**）。

```markdown
✅ 正确
# 基于 RK3576 的边缘 AI 推理研究报告

## 引言
## 方法
```

```markdown
❌ 错误 —— 三个 # 会被当成三个大标题
# 引言
# 方法
# 结论
```

**如果本文档不需要大标题**（比如只是一份普通笔记），那就让所有章节都用 `##`，一个 `#` 都不要有。

### 2. 章节一律用 `##`

`##` 会被套上 `heading 2` 样式，Word 自动生成「第1章」「第2章」……

```markdown
✅ 正确
## 引言
## 硬件架构
## 实验与结果
```

### 3. 小节用 `###`，更深用 `####`

`###` 自动生成「1.1」「1.2」；`####` 生成「1.1.1」，以此类推。

```markdown
✅ 正确
## 硬件架构

### 算力规格
#### INT8 精度
```

### 4. 标题里写不写编号都行（服务会自动处理）

**编号由 Word 自动生成**，所以标题里的手写编号是多余的。但你不必自己删 ——
转换时会**自动识别并剥掉**，识别不出来的（比如标题里的数字本来就是内容）则原样保留。

```markdown
你写什么                              转换后
## 引言                               ## 引言
## 一、引言                            ## 引言
## 1 引言                              ## 引言
## 第1章 引言                           ## 引言
### 1.1 研究背景                       ### 研究背景
### （一）研究背景                       ### 研究背景

## 3 个关键问题                         ## 3 个关键问题   ← 原样保留，
                                                         这层标题里大部分没有编号，
                                                         所以判定「3」是内容不是编号
```

判定依据是**按层级统计**：某一层里超过 60% 的标题带编号，才认为这层在用编号，整层剥离。

**摘要例外**：`## 摘要` 这个标题必须写「摘要」两个字（它是被识别出来的关键字）。

### 5. 摘要用二级标题 `## 摘要`

转换器认出这个标题后，会把它换成一个**不参与编号**的特殊样式 ——
否则摘要会占用「第1章」，导致后面所有章节编号整体错位。

```markdown
✅ 正确
## 摘要

本文研究了……

**关键词：** 关键词一；关键词二
```

### 6. 参考资料用 `## 参考资料`

章节名写 `参考资料` 或 `参考文献` 都可以（会自动变成「第N章 参考资料」）。
条目用**有序列表或无序列表**都行，转换器会拆成普通段落：

```markdown
## 参考资料

1. 作者. 文献标题[J]. 期刊名, 2024.
2. 作者. 文献标题[M]. 出版社, 2023.
```

### 7. 公式自动编号

**独立成段的公式（`$$...$$`）会自动编号**，格式是「按章」的 `（1-1）`「（2-3）」，
公式居中、编号右对齐 —— 这是中文学位论文的标准排法。

```markdown
✅ 这样写就会编号
$$y(k) = \varphi^T(k)\theta$$
```

**不想编号的公式**（比如推导过程中的中间步骤），用 fenced div 包起来：

```markdown
::: {.unnumbered}
$$K(k) = P(k-1)\varphi(k)[\lambda + \varphi^T(k)P(k-1)\varphi(k)]^{-1}$$
:::
```

**行内公式 `$...$` 不受影响**，永远不编号。

**这几种定界符都认**（AI 生成的 md 里常见的写法都能正确转成 Word 公式）：

| 写法 | 用途 |
|---|---|
| `$x^2$` | 行内公式 |
| `$$ … $$` | 独立成段的公式（会被自动编号） |
| `\(x^2\)` / `\[ … \]` | 同上两种，LaTeX 风格 —— 一样认 |
| `\begin{equation} … \end{equation}` | 同上（里面的 `\label{}` 会被去掉） |

> 其它不认识的 LaTeX 命令/环境（`align`、`gather`、`\vspace`…）**转不了** ——
> 转换报告里会把它们**列出来**，并原样保留在正文里（不会悄悄丢掉，但请改成上面这几种写法）。

> ⚠️ **正文里引用编号（公式、表、图）都要自己写、自己核对**：
> 「由式（1-2）可知」「由表2-1可知」里的编号是你手打的。
> **转换时你手写的号会被剥掉、按章重排**（写「表10」→ 排成「表4-5」，写「（2）」→ 排成「（2-2）」），
> 但**正文里手打的引用不会跟着变** —— 转换报告里也会提醒你逐条核对。

### 8. 不要用 `---`

**所有水平线都会被丢掉**（章节之间、章节内部、文档结尾 —— 一视同仁）。
论文里不需要横线；而且 pandoc 生成的那种横线在某些阅读器里会渲染成空心矩形。

```markdown
❌ 不要写
## 第一章
……

---

## 第二章
```

> 章节之间本来就会「每章另起一页」，用 `---` 分隔是多余的；
> 章节内部想分隔内容，空一行分段就够了。

### 9. 表题、图题与图片

**表题的规范位置是表格的上一行，图题是图片的下一行**（学位论文通行的
「表题在上、图题在下」），独立成段、加粗即可：

```markdown
✅ 表题写在表上方
**表1 研究技术路线**

| 阶段 | 内容 |
|---|---|
| 调研 | 文献与规范 |

✅ 图题写在图下方
![](figs/fig1.png)

**图1 系统架构**
```

**图片怎么上传**（网页端）：

- 把 `.md` 和图片**一起拖进页面** —— 图片会跟着这个 md 转换；
- 或者上传一个**压缩包**（zip / tar / tar.gz / tar.bz2 / tar.xz / 7z / rar），
  里面放 md 和图片文件夹。压缩包按文件头识别，**文件名和扩展名无所谓**。
  文件夹**叫什么都可以**
  （`figures` / `images` / `pics` / `图片` …），程序按**文件名**找；
  `figures/a.png` 和裸 `a.png` 两种写法都行。
  md 放在子目录、图片放在兄弟目录（`../figures/a.png`）也支持；
  压缩包里的其他文件（CSV / JSON / TXT 等）会被忽略，只转 `.md`。

**Obsidian 导出的写法也支持**：`![[figures/2-1.png]]` 会转成标准图片；
`![[x.png|300]]` 把 300 当宽度，`![[x.png|说明]]` 把「说明」当图题。

转换时会自动做这些事：

1. **套模板的题注样式** —— 这份模板是黑体 · 五号 · 居中；换成你自己的模板时，
   会照**你模板里的图题样式**来排（不自创版式）
2. **按章重新编号**：写「表10」→ 排成「表4-5」（第 4 章的第 5 张表），和公式编号同一套规则
3. **手写的号会被剥掉** —— 所以 `**表1 研究技术路线**` 和 `**研究技术路线**` 都行，编号交给程序
4. **图片没写题注时自动补**，文字按这个顺序取：图下加粗行 → 图片 alt → 文件名。
   文件名是纯编号（`2-1.png`）时只排「图2-1」；带说明（`云服务器架构.png`）时排
   「图2-1 云服务器架构」

> ⚠️ 只有**紧挨着**表格/插图的那一段加粗文字才会被当成题注；
> 正文里随手加粗的一句「图3 说明……」不会被改动。
> 行内图（正文里夹着的 `![](x.png)`）和**列表项里的图**只嵌入、不加题注 ——
> 它们不是独立段落。

**压缩包里有多个 md 时**：每个 md 转成一个 docx，打包成 zip 下载；
大标题取自文件名（`2. 云中的计算.md` → 大标题「云中的计算」），
md 里的 `#` 降为章。空 md 也会出一个空 docx。

> 不支持加密压缩包（服务端没法输入密码）；压缩包里的符号链接会被拒绝。
> 单文件的 `.gz` / `.bz2` / `.xz` 需要先打成 tar（图片没法单独塞进单文件压缩）。

### 10. 代码块与行内代码

**公式可以写在代码块里**，转换时会自动识别并排成 Word 公式（按章编号）：

~~~~markdown
```text
Age_scaled = (Age - 训练集年龄均值) / 训练集年龄标准差
```
~~~~

判定规则（保守）：

- ` ```math ` / ` ```latex ` / ` ```tex ` → 无条件当公式
- ` ```python ` / ` ```js ` / ` ```bash ` / ` ```sql ` 等语言标记 → 永远是代码，不动
- ` ```text ` 或无语言 → 有 `=` 之类的关系符、且没有代码语法时才当公式；
  一个块里公式和说明文字混排时，公式行转公式，说明文字转普通正文

**真代码请写语言标记**（`python`、`bash`…），或者写 ` ```code ` —— 内容再像公式
也不会转。转换结果会在网页的「需确认」里汇报，误判时改语言标记即可。

**行内代码**（`` `read_csv()` ``）会转成普通文本 —— 模板的等宽字体对中文、路径、
URL 不友好。**行内公式请用 `$…$` 写**，不要用反引号。

### 11. 列表

**无序列表（`-` / `*`）会转成正文段落**，不使用 Word 项目符号 —— 学位论文/报告的
规范做法是「分条列项用编号 + 按层级缩进」（GB/T 7713.1、各校撰写规范都不使用 •）。

- 一级项：正文段落，首行缩进 2 字
- 二级及以下：左缩进 2 字符/级，并加「（1）（2）」编号（每个父项内重新计数）
- 有序列表（`1.` / `2.`）：保留 Word 自动编号，不动

```markdown
- 第一点内容                 → 正文段落（空两字起排）
    - 子项 A                 → 左缩进 2 字，（1）子项 A
    - 子项 B                 → 左缩进 2 字，（2）子项 B
- 第二点内容                 → 正文段落
```

嵌套层级建议不超过 3 级（规范一般要求不超过 4 级）；更深的内容建议合并或写成行文。

## 二、完整示例

```markdown
# 基于 RK3576 的边缘 AI 推理研究报告

## 摘要

本文围绕 RK3576 的 NPU 能力展开……

**关键词：** 边缘计算；NPU；模型量化

## 引言

### 研究背景

正文……

### 研究意义

正文……

## 硬件架构

### 算力规格

**表1 精度与算力**

| 精度 | 算力 |
|------|------|
| INT8 | 6 TOPS |

### 存储层次

正文……

## 参考资料

1. Rockchip. RK3576 Brief Datasheet[Z]. 2024.
2. 作者. 文献名[J]. 期刊, 2023.
```

## 三、附：给 AI 的提示词

如果你手上已经有一份 markdown，但它不符合上面的规范，**把下面这段连同你的 markdown 一起发给 AI**，
它会帮你改写成合规版本。

````text
你是一名技术文档编辑。请把我提供的 markdown 文档改写成符合以下规范的版本。

【目标规范】

1. 一级标题 `#` 最多只能有一个，且必须是**文档大标题**（整篇文档的题目）。
   - 如果原文有多个 `#`，判断哪个是文档题目：它是题目就保留为 `#`，其余的都降级为 `##`。
   - 如果原文根本没有文档题目（`#` 都是当章节用的），就把**所有** `#` 都降级为 `##`，不要自己编一个标题。
   - 如果原文没有题目、但内容明显需要一个标题，可以在最前面加一个 `#`，标题从正文内容概括。

2. 章节标题统一用 `##`。小节用 `###`，更下一层用 `####`，最多到 `######`。
   不要跳级（例如 `##` 下面直接接 `####`）。

3. **所有标题里都不许有编号。** 删除这些形式的手写编号：
   - 中文数字：`一、` `二、` `（三）` `第三章 ` 等
   - 阿拉伯数字：`1.` `1.1` `1.1.1` `第1节 ` 等
   - 字母：`A.` `(1)` 等
   编号由 Word 自动生成，手写会造成双重编号。
   唯一例外：`## 摘要` 这个标题要保留「摘要」二字，因为它是转换器的识别关键字。

4. 「摘要」必须是 `## 摘要` 的形式，位于文档最前面（大标题之后）。
   摘要正文照原样保留，「关键词」那一行保留加粗写法。

5. 「参考资料 / 参考文献」章节标题用 `##`，名称写「参考资料」或「参考文献」。
   条目可以用有序列表（`1.` `2.`）或无序列表（`-` `-`），不要写成普通段落。

6. **删除所有的 `---`**（水平线一律不用：章节之间靠「每章另起一页」分隔，
   章节内部空行分段就够了）。转换时它们也会被全部丢掉。

7. **表格的标题写在表格的上一行、图片的标题写在图片的下一行**，独立成段、加粗即可：
   ```markdown
   **表1 研究技术路线**

   | 阶段 | 内容 |
   |---|---|
   | 调研 | 文献与规范 |

   ![](figs/fig1.png)

   **图1 系统架构**
   ```
   标题里的编号可以写也可以不写（`**表1 研究技术路线**` 或 `**研究技术路线**` 都行）——
   转换时会剥掉手写编号、按章重新编号（表10 → 表4-5）。

8. **公式**：独立成段的公式用 `$$ … $$`，行内用 `$ … $`。
   **不要用** `\begin{align}` `\begin{gather}` 这类环境（转不了，会被原样留在正文里）。
   公式里**不要手写编号**（`\tag{}` 会被丢掉，编号自动按章生成）。

9. 其余内容（段落、表格、代码块、图片、脚注、引用）**原样保留，不要改写、不要润色、不要增删内容**。
   你的任务只是调整标题层级和编号，不是编辑内容。

【输出要求】
- 只输出改写后的完整 markdown，不要输出解释、不要用代码块包裹。
- 不要问我问题，按你的最佳判断处理。
````

## 四、如果转换时报了警告怎么办

转换时如果看到类似这样的提示：

```
[WARNING] 文档里有 3 个一级标题（#），无法判断哪个是论文大标题：
    1. 引言
    2. 方法
    3. 结论
```

说明你的 markdown 第 1 条违规了。按上面第三节的提示词让 AI 改一遍，或者手工把多余的 `#` 改成 `##`。
