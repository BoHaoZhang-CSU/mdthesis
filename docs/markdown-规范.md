# Markdown 书写规范

这份规范描述「用本项目的转换器生成 Word 论文」时，markdown 应该怎么写。

**为什么需要规范**：转换器把 markdown 的标题层级映射到 Word 的样式，再交给模板自动编号和分页。
层级用错，输出就会错位 —— 而且**不一定报错**，只是悄悄变丑。所以请照着写。

---

## 一、规范正文

### 1. 一级标题 `#` 只能出现一次，且只能是文档大标题

文档大标题会被套上「摘要上标题」样式（黑体、18pt、居中、**不编号**）。

```markdown
✅ 正确
# 基于 RK3576 的边缘 AI 推理研究报告

## 引言
## 方法
```

```markdown
❌ 错误 —— 三个 # 会被当成三个大标题
# 引言
# 方法
# 结论
```

**如果本文档不需要大标题**（比如只是一份普通笔记），那就让所有章节都用 `##`，一个 `#` 都不要有。

### 2. 章节一律用 `##`

`##` 会被套上 `heading 2` 样式，Word 自动生成「第1章」「第2章」……

```markdown
✅ 正确
## 引言
## 硬件架构
## 实验与结果
```

### 3. 小节用 `###`，更深用 `####`

`###` 自动生成「1.1」「1.2」；`####` 生成「1.1.1」，以此类推。

```markdown
✅ 正确
## 硬件架构

### 算力规格
#### INT8 精度
```

### 4. 标题里写不写编号都行（服务会自动处理）

**编号由 Word 自动生成**，所以标题里的手写编号是多余的。但你不必自己删 ——
转换时会**自动识别并剥掉**，识别不出来的（比如标题里的数字本来就是内容）则原样保留。

```markdown
你写什么                              转换后
## 引言                               ## 引言
## 一、引言                            ## 引言
## 1 引言                              ## 引言
## 第1章 引言                           ## 引言
### 1.1 研究背景                       ### 研究背景
### （一）研究背景                       ### 研究背景

## 3 个关键问题                         ## 3 个关键问题   ← 原样保留，
                                                         这层标题里大部分没有编号，
                                                         所以判定「3」是内容不是编号
```

判定依据是**按层级统计**：某一层里超过 60% 的标题带编号，才认为这层在用编号，整层剥离。

**摘要例外**：`## 摘要` 这个标题必须写「摘要」两个字（它是被识别出来的关键字）。

### 5. 摘要用二级标题 `## 摘要`

转换器认出这个标题后，会把它换成一个**不参与编号**的特殊样式 ——
否则摘要会占用「第1章」，导致后面所有章节编号整体错位。

```markdown
✅ 正确
## 摘要

本文研究了……

**关键词：** 关键词一；关键词二
```

### 6. 参考资料用 `## 参考资料`

章节名写 `参考资料` 或 `参考文献` 都可以（会自动变成「第N章 参考资料」）。
条目用**有序列表或无序列表**都行，转换器会拆成普通段落：

```markdown
## 参考资料

1. 作者. 文献标题[J]. 期刊名, 2024.
2. 作者. 文献标题[M]. 出版社, 2023.
```

### 7. 不要用 `---` 做章节分隔

章节之间靠「每章另起一页」分隔，不需要横线。

```markdown
❌ 错误
## 第一章
……

---

## 第二章
```

> 章节**内部**的 `---` 是允许的（会渲染成一条正常横线），但章节之间的分会自动处理，写了是多余的。

## 二、完整示例

```markdown
# 基于 RK3576 的边缘 AI 推理研究报告

## 摘要

本文围绕 RK3576 的 NPU 能力展开……

**关键词：** 边缘计算；NPU；模型量化

## 引言

### 研究背景

正文……

### 研究意义

正文……

## 硬件架构

### 算力规格

| 精度 | 算力 |
|------|------|
| INT8 | 6 TOPS |

### 存储层次

正文……

## 参考资料

1. Rockchip. RK3576 Brief Datasheet[Z]. 2024.
2. 作者. 文献名[J]. 期刊, 2023.
```

## 三、附：给 AI 的提示词

如果你手上已经有一份 markdown，但它不符合上面的规范，**把下面这段连同你的 markdown 一起发给 AI**，
它会帮你改写成合规版本。

````text
你是一名技术文档编辑。请把我提供的 markdown 文档改写成符合以下规范的版本。

【目标规范】

1. 一级标题 `#` 最多只能有一个，且必须是**文档大标题**（整篇文档的题目）。
   - 如果原文有多个 `#`，判断哪个是文档题目：它是题目就保留为 `#`，其余的都降级为 `##`。
   - 如果原文根本没有文档题目（`#` 都是当章节用的），就把**所有** `#` 都降级为 `##`，不要自己编一个标题。
   - 如果原文没有题目、但内容明显需要一个标题，可以在最前面加一个 `#`，标题从正文内容概括。

2. 章节标题统一用 `##`。小节用 `###`，更下一层用 `####`，最多到 `######`。
   不要跳级（例如 `##` 下面直接接 `####`）。

3. **所有标题里都不许有编号。** 删除这些形式的手写编号：
   - 中文数字：`一、` `二、` `（三）` `第三章 ` 等
   - 阿拉伯数字：`1.` `1.1` `1.1.1` `第1节 ` 等
   - 字母：`A.` `(1)` 等
   编号由 Word 自动生成，手写会造成双重编号。
   唯一例外：`## 摘要` 这个标题要保留「摘要」二字，因为它是转换器的识别关键字。

4. 「摘要」必须是 `## 摘要` 的形式，位于文档最前面（大标题之后）。
   摘要正文照原样保留，「关键词」那一行保留加粗写法。

5. 「参考资料 / 参考文献」章节标题用 `##`，名称写「参考资料」或「参考文献」。
   条目可以用有序列表（`1.` `2.`）或无序列表（`-` `-`），不要写成普通段落。

6. **删除所有独立成行的 `---`**（章节之间不需要横线分隔）。
   但如果 `---` 是出现在章节内部、用于分隔内容的，保留它。

7. 其余内容（段落、表格、代码块、图片、脚注、引用）**原样保留，不要改写、不要润色、不要增删内容**。
   你的任务只是调整标题层级和编号，不是编辑内容。

【输出要求】
- 只输出改写后的完整 markdown，不要输出解释、不要用代码块包裹。
- 不要问我问题，按你的最佳判断处理。
````

## 四、如果转换时报了警告怎么办

转换时如果看到类似这样的提示：

```
[WARNING] 文档里有 3 个一级标题（#），无法判断哪个是论文大标题：
    1. 引言
    2. 方法
    3. 结论
```

说明你的 markdown 第 1 条违规了。按上面第三节的提示词让 AI 改一遍，或者手工把多余的 `#` 改成 `##`。
